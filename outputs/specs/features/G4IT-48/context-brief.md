## 3. Conventions

- CSV column names are French camelCase (`nomEquipementPhysique`, `quantite`, `paysDUtilisation`); Java/DB use English (`quantity`, `in_physical_equipment`). Feature text mixes `contexteUsage`/`usageContext` — CSV names follow the French convention.
- Layering: generated OpenAPI interface → controller → business service → repository; MapStruct mappers for DTO/entity/CSV.
- Backend messages in `messages.properties` / `messages_fr.properties`; frontend i18n in `assets/i18n/en.json`, `fr.json`.
- Tests: backend JUnit under `services/backend/src/test`; frontend `*.spec.ts` alongside sources (e.g. `inventory-util.service.spec.ts`).

## 4. Integration points

- PostgreSQL (`in_physical_equipment`, `out_physical_equipment`, indicator views).
- NumEcoEval calculation library invoked from `EvaluateNumEcoEvalService` (impacts per criterion × lifecycle step).

- File storage (`services/backend/storage`) for import/rejected/export files; Keycloak for authZ.
